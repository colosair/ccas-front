# 민원분류지원시스템(CCAS, Civil Complaint Assistance System) 기획서

## 1. 프로젝트 개요

### 1.1 프로젝트명

**민원분류지원시스템(CCAS, Civil Complaint Assistance System)**

### 1.2 한 줄 소개

Code 4급 비긴급 경찰 민원을 대상으로, 통화 녹취와 민원 텍스트를 AI가 후처리하여 요약·정리하고, 유사 사례 기반으로 담당 부서 또는 타기관 이관 후보를 제안하는 경찰 내부 업무 보조 플랫폼이다.

### 1.3 프로젝트 정의

본 프로젝트는 경찰 민원 상담 및 접수 과정에서 발생하는 반복적인 청취, 요약, 분류, 이관 판단 보조 업무를 줄이기 위한 내부 행정지원 시스템이다.

민원인이 직접 사용하는 대민 서비스가 아니라, 경찰 내부 상담 담당자와 민원 처리 담당자가 사용하는 업무 보조 플랫폼으로 설계한다. AI는 민원을 직접 처리하거나 최종 판단하지 않으며, 담당자가 검토할 수 있는 정리본, 분류 후보, 유사 사례, 이관 후보를 제공하는 역할을 수행한다.

본 서비스의 핵심 대상은 긴급 출동이 필요한 112 신고가 아니라, Code 4급 수준의 비긴급 민원이다. 따라서 긴급성 판단, 현장 출동 판단, 생명·신체 위험 상황 대응은 본 프로젝트의 핵심 범위에서 제외한다.

## 2. 추진 배경 및 문제 정의

### 2.1 추진 배경

경찰 민원 창구에는 실제 경찰 소관 민원뿐 아니라 지자체, 소비자원, 안전신문고 등 타기관으로 이관되어야 하는 민원도 함께 유입된다. 특히 비긴급 민원은 즉각적인 현장 출동보다 정확한 내용 파악, 소관 분류, 담당 부서 또는 타기관 안내가 중요하다.

하지만 상담 담당자는 통화 내용을 직접 청취하고, 민원 내용을 요약하며, 적절한 분류와 이관 대상을 판단해야 한다. 이 과정은 반복적이고 시간이 많이 소요되며, 담당자의 경험에 따라 분류 품질이 달라질 수 있다.

이에 따라 본 프로젝트는 AI를 활용하여 비긴급 민원의 후처리 과정을 지원하고, 담당자가 더 빠르고 일관되게 민원을 검토할 수 있도록 돕는 것을 목표로 한다.

### 2.2 핵심 문제

1. 비긴급 민원도 접수 후 내용 파악과 요약에 시간이 소요된다.
2. 경찰 소관 민원과 타기관 소관 민원이 혼재되어 있다.
3. 민원 유형별 담당 부서 또는 이관 기관 판단이 반복적으로 발생한다.
4. 실제 경찰 신고·민원 세부 데이터는 외부에서 확보하기 어렵다.
5. 대규모 로컬 모델 학습은 해커톤 또는 MVP 단계에서 구현 부담이 크다.
6. 상담 담당자가 AI 결과를 신뢰하려면 추천 근거와 유사 사례가 함께 제시되어야 한다.

## 3. 프로젝트 목표

### 3.1 서비스 목표

본 프로젝트의 목표는 비긴급 경찰 민원의 후처리 업무를 AI로 보조하여 담당자의 업무 부담을 줄이고, 민원 분류와 이관 판단의 일관성을 높이는 것이다.

### 3.2 세부 목표

- 녹취 음성을 STT로 텍스트화한다.
- 전사문 또는 민원 텍스트를 내부 템플릿에 맞게 요약·정리한다.
- 정리된 민원 내용을 기반으로 벡터 DB에서 유사 사례를 검색한다.
- 유사도 기반으로 민원 분류 후보 Top-N을 제시한다.
- 담당 부서 또는 타기관 이관 후보를 제안한다.
- 담당자가 최종 선택·수정할 수 있도록 결과를 카드 형태로 제공한다.
- 담당자의 최종 선택 결과를 피드백 데이터로 저장한다.

## 5. 핵심 서비스 구조

본 서비스의 전체 흐름은 다음과 같다.

```text
경찰 내부 담당자 로그인
↓
녹취 파일 업로드 또는 텍스트 입력
↓
STT를 통한 음성 → 텍스트 변환
↓
LLM을 통한 템플릿 기반 요약·정리
↓
정리본 임베딩 변환
↓
pgvector 기반 유사 사례 검색
↓
분류 후보 Top-N 및 이관 후보 제안
↓
담당자 검토·수정·확정
↓
피드백 저장
```

이 구조에서 AI는 다음 세 가지 역할을 담당한다.

1. **STT**: 음성 데이터를 텍스트로 변환한다.
2. **LLM 요약·정리**: 전사문을 내부 템플릿에 맞게 구조화한다.
3. **RAG 기반 분류 보조**: 정리본과 벡터 DB 내 기준 데이터 간 유사도를 비교하여 분류 후보와 이관 후보를 제안한다.

## 6. AI 기능 설계

### 6.1 STT 기능

STT 기능은 통화 녹취 파일을 입력받아 텍스트 전사문을 생성한다.

```text
녹취 파일
→ STT API 또는 모델
→ 전사문 생성
→ 담당자 화면 표시
```

MVP에서는 실시간 STT가 아니라, 통화 종료 후 녹음 파일을 업로드하고 처리하는 후처리 방식을 사용한다.

### 6.2 템플릿 기반 요약·정리

STT 결과 또는 직접 입력된 민원 텍스트는 LLM을 통해 내부 템플릿에 맞게 정리된다.

예상 출력 구조는 다음과 같다.

```json
{
  "complaint_summary": "민원 핵심 요약",
  "main_issue": "주요 쟁점",
  "requested_action": "민원인이 원하는 조치",
  "location": "발생 장소",
  "time": "발생 시점",
  "related_party": "상대방 또는 관련 대상",
  "evidence": "첨부자료 또는 증거 여부",
  "missing_info": ["추가 확인이 필요한 정보"],
  "keywords": ["핵심 키워드"]
}
```

이 단계의 목적은 AI가 바로 민원을 확정 분류하는 것이 아니라, 이후 벡터 검색에 적합한 정리본을 생성하는 것이다.

### 6.3 RAG 기반 유사도 분류

정리된 민원 내용은 임베딩으로 변환된 뒤, pgvector에 저장된 기존 분류 기준 데이터와 비교된다.

```text
정리된 민원 텍스트
→ 임베딩 생성
→ pgvector 유사도 검색
→ 유사 사례 Top-N 조회
→ 분류 후보 및 이관 후보 생성
```

결과는 단일 확정값이 아니라 Top-N 후보로 제공한다.

예상 출력은 다음과 같다.

```json
{
  "top_candidates": [
    {
      "rank": 1,
      "category": "불법주정차",
      "target_agency": "관할 지자체 교통과",
      "similarity": 0.87,
      "reason": "주차 차량으로 인한 통행 불편 내용과 유사"
    },
    {
      "rank": 2,
      "category": "도로 통행 불편",
      "target_agency": "관할 지자체 도로관리부서",
      "similarity": 0.79,
      "reason": "도로 점유 및 통행 방해 민원과 유사"
    },
    {
      "rank": 3,
      "category": "생활불편 민원",
      "target_agency": "안전신문고 또는 지자체 생활민원",
      "similarity": 0.71,
      "reason": "생활불편 유형의 일반 민원과 유사"
    }
  ],
  "review_required": true
}
```

## 7. 데이터 전략

### 7.1 데이터 확보 방향

본 프로젝트는 실제 경찰 신고·민원 세부 내용을 직접 확보하기 어렵다는 한계를 전제로 한다. 따라서 데이터는 다음과 같이 구분하여 활용한다.

| 데이터 | 확보 가능성 | 활용 방식 |
|---|---|---|
| 국민신문고 데이터 | 내용 확인 가능 | 타기관 민원 사례, 이관 기준 데이터 |
| 새올 공개 상담민원 | 내용 확인 가능 | 실제 시민 표현, 타기관 분류 사례 |
| 110 상담사례 | 질문·답변·기관 코드 활용 가능 | 기관 안내, 타기관 소관 분류 |
| 경찰민원24 | 세부 민원 원문보다는 민원명·서식·기준 중심 | 경찰 소관 기준표 |
| 범죄 신고 분류표 | 기준 데이터로 활용 | 경찰 내부 분류 기준 |
| 담당 조직표 | 기준 데이터로 활용 | 부서 매핑 기준 |
| 팀 임의 생성 데이터 | 직접 생성 | 시연용 경찰 민원 분류 데이터 |

### 7.2 경찰 민원 데이터 부족 보완 방식

경찰 신고·민원 세부 내용은 열람이 어렵기 때문에, 다음 방식으로 시연용 분류 데이터를 구축한다.

1. 경찰민원24의 민원명, 서식명, 안내 내용을 수집한다.
2. 범죄 신고 분류표와 담당 조직표를 바탕으로 내부 분류 기준을 만든다.
3. 경찰 소관 민원에 해당하는 예시 문장을 팀에서 직접 작성한다.
4. 생성 데이터에는 `SYNTHETIC_POLICE_CASE` 라벨을 부여한다.
5. 해당 데이터는 실제 운영용이 아니라 MVP 시연용 기준 데이터로 사용한다.

예시 데이터는 다음과 같다.

| 예시 민원 문장 | 분류 | 담당 후보 |
|---|---|---|
| 중고거래로 돈을 보냈는데 물건을 받지 못했습니다 | 사기/사이버 | 수사과 또는 사이버수사 |
| 지갑을 잃어버렸는데 어디에 신고해야 하나요 | 유실물 | 유실물 담당/LOST112 |
| 교통사고 사실확인원이 필요합니다 | 교통민원 | 교통과 |
| 경찰관 응대가 불친절했습니다 | 청문감사 | 청문감사 |
| 고소장을 접수하려면 어떤 서류가 필요한가요 | 수사절차 | 민원실/수사과 |

## 8. 데이터베이스 설계

### 8.1 DB 설계 방향

본 프로젝트의 핵심 저장소는 벡터 DB이다. 민원 정리본과 기준 데이터를 임베딩 형태로 저장하고, 신규 민원과 기존 기준 데이터 간 유사도 검색을 수행해야 하기 때문이다.

기술적으로는 PostgreSQL에 pgvector를 적용하는 방식을 우선 고려한다. 이를 통해 일반 관계형 데이터와 벡터 데이터를 하나의 DB에서 함께 관리할 수 있다.

### 8.2 DB 역할 구분

| 저장 영역 | 주요 역할 |
|---|---|
| RDB 영역 | 사용자 인증, 권한 관리, 민원 처리 이력, 담당자 피드백 |
| Vector DB 영역 | 민원 기준 데이터, 유사 사례, 임베딩 검색, 분류 후보 추천 |

PostgreSQL + pgvector를 사용할 경우 물리적으로는 하나의 DB를 사용하되, 논리적으로 RDB 영역과 Vector DB 영역을 나누어 설계한다.

### 8.3 주요 테이블

#### 사용자 테이블

```sql
CREATE TABLE users (
    user_id BIGSERIAL PRIMARY KEY,
    login_id VARCHAR(100) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    name VARCHAR(100) NOT NULL,
    role VARCHAR(30) NOT NULL,
    department VARCHAR(100),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### 민원 처리 케이스 테이블

```sql
CREATE TABLE complaint_case (
    case_id BIGSERIAL PRIMARY KEY,
    user_id BIGINT REFERENCES users(user_id),
    input_type VARCHAR(30) NOT NULL,
    original_text TEXT,
    stt_text TEXT,
    structured_summary JSONB,
    status VARCHAR(30) DEFAULT 'RECEIVED',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### 벡터 분류 기준 테이블

```sql
CREATE TABLE complaint_vector_index (
    vector_id BIGSERIAL PRIMARY KEY,
    source_type VARCHAR(50) NOT NULL,
    category_code VARCHAR(50),
    category_name VARCHAR(100),
    jurisdiction_type VARCHAR(50),
    target_agency VARCHAR(150),
    target_department VARCHAR(150),
    title TEXT,
    content TEXT NOT NULL,
    keywords TEXT[],
    is_synthetic BOOLEAN DEFAULT FALSE,
    embedding VECTOR(1536),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### AI 분석 결과 테이블

```sql
CREATE TABLE ai_analysis_result (
    result_id BIGSERIAL PRIMARY KEY,
    case_id BIGINT REFERENCES complaint_case(case_id),
    summary TEXT,
    top_candidates JSONB,
    recommended_action TEXT,
    confidence_score NUMERIC(5,4),
    llm_response JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### 담당자 피드백 테이블

```sql
CREATE TABLE officer_feedback (
    feedback_id BIGSERIAL PRIMARY KEY,
    case_id BIGINT REFERENCES complaint_case(case_id),
    selected_category_code VARCHAR(50),
    selected_target_agency VARCHAR(150),
    selected_department VARCHAR(150),
    correction_reason TEXT,
    confirmed_by BIGINT REFERENCES users(user_id),
    confirmed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 17. 최종 요약

본 프로젝트는 긴급 신고 대응 시스템이 아니라, Code 4급 비긴급 민원을 대상으로 하는 경찰 내부 후처리 보조 플랫폼이다.

AI는 STT, 템플릿 요약, RAG 기반 유사도 검색을 수행하며, 로컬 학습이나 파인튜닝보다는 LLM API 호출과 pgvector 기반 벡터 검색을 중심으로 구현한다.

실제 경찰 민원 세부 데이터 확보가 어렵기 때문에, 경찰민원24와 범죄 신고 분류표, 담당 조직표를 기준으로 시연용 경찰 민원 데이터를 임의 생성하여 활용한다. 국민신문고, 새올, 110 상담사례 등 타기관 데이터는 실제 시민 표현과 이관 기준 데이터로 활용한다.

서비스 사용자는 민원인이 아니라 경찰 내부 담당자이며, 처리 방식은 실시간이 아닌 통화 종료 후 후처리 방식이다. 최종 판단은 항상 담당자가 수행하고, AI는 요약·정리·분류 후보·이관 후보를 제공하는 보조 역할을 담당한다.

## 18. 발표용 핵심 문장

민원분류지원시스템(CCAS, Civil Complaint Assistance System)은 긴급 신고 대응 시스템이 아니라, Code 4급 비긴급 민원을 대상으로 경찰 내부 담당자의 통화 후처리, 민원 요약, 유사 사례 기반 분류, 담당 부서 및 타기관 이관 제안을 지원하는 AI 기반 내부 업무 보조 플랫폼이다.

조금 더 전략적으로 표현하면 다음과 같다.

CCAS는 비긴급 경찰 민원 처리 과정에서 발생하는 반복적인 청취, 요약, 분류, 이관 판단 보조 업무를 STT, LLM 템플릿 요약, RAG 기반 유사도 검색으로 자동화하여 담당자의 판단 부담을 줄이고 민원 처리의 일관성과 효율성을 높이는 내부 행정지원 플랫폼이다.
